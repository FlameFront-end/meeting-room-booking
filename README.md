# Бронирование переговорной

Интерфейс бронирования переговорной комнаты в течение рабочего дня (09:00–18:00).

- **Демо:** [meeting-room-booking-xi-seven.vercel.app](https://meeting-room-booking-xi-seven.vercel.app)
- **Стек:** Next.js 16 (App Router), React 19, TypeScript (strict), TanStack Query, React Hook Form + Zod, MSW, SCSS Modules
- **Тесты:** Vitest + Testing Library, Playwright (desktop + mobile)

## Как запустить

Нужен Node.js 22+ (версия в `.nvmrc`).

```bash
npm install
npm run dev          # http://localhost:3000
```

| Команда            | Что делает                                                          |
| ------------------ | ------------------------------------------------------------------- |
| `npm run build`    | прод-сборка                                                         |
| `npm run check`    | типы, линтеры, форматирование, unit и integration тесты             |
| `npm run test:e2e` | Playwright; перед первым запуском `npx playwright install chromium` |

Реального бэкенда нет: mock API на MSW работает прямо в браузере, данные хранятся в `localStorage`.

## Что сделано

### Возможности пользователя

| Требование ТЗ                      | Как сделано                                                                    |
| ---------------------------------- | ------------------------------------------------------------------------------ |
| Выбрать дату                       | Стрелки по дням, «Сегодня», календарь. Дата хранится в URL (`?date=`)          |
| Посмотреть брони на выбранную дату | Сетка дня 09:00–18:00: брони — блоки по реальному времени                      |
| Выбрать время начала и окончания   | Списки с шагом 15 минут и быстрый выбор длительности (30 мин, 1 ч, 1,5 ч, 2 ч) |
| Создать бронь                      | Кнопка «Новая бронь» или клик по свободному времени в сетке                    |
| Редактировать бронь                | Клик по брони открывает форму                                                  |
| Удалить бронь                      | Из формы редактирования, с подтверждением                                      |

### Бизнес-правила

Правила — чистые функции в `entities/booking/model/rules.ts`. Одна и та же `validateBooking` даёт подсказки в форме до отправки и проверяет запрос в mock-сервере.

| Правило ТЗ                                   | Как сделано                                                                                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1. В пределах рабочего дня                   | Начало 09:00–17:30, окончание 09:30–18:00                                                                                                        |
| 2. start < end                               | Подсказка «Окончание раньше начала»                                                                                                              |
| 3–4. От 30 минут до 2 часов                  | Подсказки «Минимум 30 мин» / «Максимум 2 ч»; варианты длительности за концом дня недоступны                                                      |
| 5. Без пересечений, касание границ допустимо | Интервалы полуоткрытые `[start, end)`: 10:00–11:00 и 11:00–12:00 совместимы                                                                      |
| 6. Нельзя бронировать прошедшее время        | На сегодня прошедшие варианты недоступны; на прошедшую дату «Новая бронь» заблокирована                                                          |
| 7. Бронь не конфликтует сама с собой         | При редактировании текущая бронь исключается из проверки                                                                                         |
| 8. Сервер может вернуть 409                  | Форма не закрывается и не теряет данные, показывается сообщение со списком конфликтов, список броней обновляется, конфликтующая бронь подсвечена |

Как проверить 409 вручную: открыть демо с `?mock-conflict=once` — следующую запись «займёт другой сотрудник» за мгновение до отправки.

### Что важно показать

- **Бизнес-логика и валидация.** Правила покрыты unit-тестами, включая границы (ровно 30 минут, ровно 2 часа, касание интервалов).
- **Состояния UI.** Загрузка (скелетон сетки), пусто, ошибка с «Повторить», отправка формы (кнопка в состоянии загрузки, повторная отправка невозможна).
- **Серверные ошибки.** 409 — конфликт, 422 — нарушения правил у полей, 404 — бронь уже удалили, сеть и 5xx — данные формы сохраняются, можно отправить ещё раз.
- **Разделение API и UI.** Компоненты знают только хуки TanStack Query, хуки — тип `BookingsApi`, тот — `HttpClient`. Для настоящего бэкенда достаточно `NEXT_PUBLIC_API_BASE_URL` и `NEXT_PUBLIC_API_MOCKING=disabled`.
- **TypeScript.** `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`; ответы сервера проверяются Zod.
- **Адаптивность и доступность.** Модальные окна на нативном `<dialog>` (Esc, возврат фокуса, на мобиле — лист снизу); списки и календарь работают с клавиатуры по паттернам WAI-ARIA; ошибки связаны с полями через `aria-describedby`; конфликт отмечается текстом, а не только цветом. E2E проходят на desktop и Pixel 7.

### Mock API

Контракт из ТЗ, описан в `entities/booking/api/contract.ts`:

```
GET    /api/bookings?date=YYYY-MM-DD   → 200 Booking[]
POST   /api/bookings                   → 201 Booking
PATCH  /api/bookings/:id               → 200 Booking
DELETE /api/bookings/:id               → 204
```

Ошибки — `{ error: { code, message, details? } }`: 409 с `details.conflicts`, 422 с `details.violations`.

## Архитектура

Слои в духе Feature-Sliced Design; границы проверяет ESLint (`eslint.config.mjs`).

```
app/            Next.js-роутинг
src/
  core/         провайдеры, QueryClient, запуск mock API, глобальные стили
  screens/      экран дня
  widgets/      сетка дня, статус комнаты
  features/     выбор даты, форма брони, удаление
  entities/     бронь: схемы, правила, API, карточка
  shared/       HTTP-клиент, утилиты дат и времени, UI-компоненты
  mock-server/  обработчики MSW, хранилище, сценарии
e2e/            Playwright
```

## Решения по неоднозначностям ТЗ

| Вопрос                                       | Решение                                                                                      |
| -------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Чья таймзона определяет «сегодня»            | Таймзона пользователя                                                                        |
| Можно ли менять или удалять начавшуюся бронь | Нет: начавшиеся и прошедшие брони только для чтения (сервер отвечает `422 BOOKING_LOCKED`)   |
| Бронь, начинающаяся в текущую минуту         | Разрешена: прошедшим считается время строго раньше текущей минуты                            |
| Границы длительности                         | Включительно: ровно 30 минут и ровно 2 часа допустимы                                        |
| Шаг выбора времени                           | 15 минут: 30 — слишком грубо (10:15–10:45 не забронировать), 5 — больше 100 пунктов в списке |
| Пустое название                              | Не хранится, в интерфейсе — «Без названия»                                                   |
