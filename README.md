# Бронирование переговорной

Интерфейс бронирования переговорной комнаты в течение рабочего дня (09:00–18:00): просмотр броней на дату, создание, редактирование и удаление с проверкой бизнес-правил на клиенте и на сервере.

- **Стек:** Next.js 16 (App Router), React 19, TypeScript (strict), TanStack Query, React Hook Form + Zod, MSW, SCSS Modules
- **Тесты:** Vitest + Testing Library (unit/integration), Playwright (e2e, desktop + mobile)

## Запуск

Нужен Node.js 22+ (версия в `.nvmrc`).

```bash
npm install
npm run dev          # http://localhost:3000
```

Реального бэкенда нет: API имитирует MSW прямо в браузере (Service Worker). Данные сохраняются в `localStorage`, поэтому переживают перезагрузку страницы.

| Команда                 | Что делает                                                          |
| ----------------------- | ------------------------------------------------------------------- |
| `npm run dev`           | dev-сервер                                                          |
| `npm run build`         | прод-сборка                                                         |
| `npm run check`         | всё, что проверяет CI, кроме сборки и e2e: типы, линтеры, тесты     |
| `npm test`              | unit и integration тесты                                            |
| `npm run test:coverage` | то же с покрытием (`coverage/index.html`)                           |
| `npm run test:e2e`      | Playwright; перед первым запуском `npx playwright install chromium` |
| `npm run lint:fix`      | автоисправление ESLint                                              |
| `npm run format`        | Prettier                                                            |

## Mock-сервер и ручная проверка сценариев

Сервер валидирует все бизнес-правила и возвращает `409`, если слот занят. Чтобы воспроизвести состояния, которые сложно поймать вручную, есть сценарии:

| Как включить                    | Что происходит                                                                     |
| ------------------------------- | ---------------------------------------------------------------------------------- |
| `?mock-conflict=once`           | следующая запись получит `409`: слот «займёт другой сотрудник» за мгновение до вас |
| `?mock-conflict=always`         | так же для каждой записи                                                           |
| `?mock-latency=2000`            | задержка ответа в мс (по умолчанию 400, чтобы были видны состояния загрузки)       |
| `?mock-fail-list=1`             | загрузка списка падает с `500`                                                     |
| `mockServer.setScenario({...})` | то же из консоли браузера                                                          |
| `mockServer.reset()`            | вернуть демо-данные и сценарий по умолчанию                                        |

Сценарий запоминается на время сессии вкладки.

## Архитектура

Код разложен по слоям в духе Feature-Sliced Design. Слой импортирует только из слоёв ниже себя, а слайсы — только через публичный `index.ts`. Это не договорённость, а правило ESLint (`import/no-restricted-paths` и `no-restricted-imports` в `eslint.config.mjs`).

```
app/                     Next.js-роутинг: layout, page, error. Только собирает экраны.
src/
  core/                  инициализация приложения: провайдеры, QueryClient, запуск mock-API, глобальные стили
  screens/               экраны (страницы): компонуют виджеты и фичи
    booking-day/
  widgets/               самостоятельные блоки интерфейса
    day-schedule/        расписание дня: загрузка, пусто, ошибка, список
  features/              пользовательские сценарии
    select-date/         выбор даты, синхронизация с URL (?date=)
    booking-form/        создание и редактирование брони: форма, живая проверка правил, ошибки сервера
    delete-booking/      удаление с подтверждением
  entities/              бизнес-сущности
    booking/
      model/             схемы Zod, типы, бизнес-правила, варианты времени, тексты нарушений
      api/               контракт API, bookingsApi, query-ключи и хуки TanStack Query
      ui/                BookingCard
  shared/                переиспользуемое, без знания о предметной области
    api/                 HTTP-клиент, ApiError
    lib/                 время, даты, React-хуки
    ui/                  Button, Spinner, Alert, Dialog, Field
    config/              переменные окружения
    styles/              токены и миксины SCSS
  mock-server/           имитация бэкенда (MSW): обработчики, хранилище, сценарии
  test/                  тестовая инфраструктура
e2e/                     Playwright
```

### Ключевые решения

- **Бизнес-правила — чистые функции** (`entities/booking/model/rules.ts`). Одна и та же `validateBooking` даёт подсказки в форме до отправки и делает финальную проверку в mock-сервере. «Сейчас» передаётся параметром, поэтому правила детерминированы и тестируются без моков времени.
- **Время считается в минутах от полуночи.** `"10:30"` → `630`; пересечение — это `aStart < bEnd && bStart < aEnd` на полуинтервалах, касание границ конфликтом не считается. `Date` и таймзоны в бизнес-логике не участвуют.
- **Сетевой слой отделён от UI.** Компоненты знают только хуки TanStack Query, хуки — только тип `BookingsApi`, тот — только `HttpClient`. Чтобы подключить настоящий бэкенд, достаточно задать `NEXT_PUBLIC_API_BASE_URL` и `NEXT_PUBLIC_API_MOCKING=disabled`.
- **Ответы сервера валидируются Zod.** Кривой ответ превращается в понятную ошибку, а не в `undefined` где-то в рендере.
- **Ошибки типизированы.** HTTP-клиент превращает всё (сеть, отмена, 4xx, 5xx, кривой JSON) в `ApiError` с `kind` и `code`. UI решает, что показать, по ним, а не по статусам.
- **409 — штатная ситуация.** Мутации инвалидируют список и при успехе, и при ошибке, так что после конфликта UI сразу видит чужую бронь. Конфликтующие брони приходят в `details.conflicts`.
- **Mock-сервер работает в браузере, а не в Route Handlers.** На Vercel serverless-функции не делят память между инстансами: in-memory store терял бы данные между запросами. MSW + `localStorage` даёт стабильное демо без бэкенда, а те же обработчики используются в тестах через `msw/node`.
- **Выбранная дата хранится в URL.** Ссылкой можно поделиться, работают «назад/вперёд».
- **«Сегодня» вычисляется только на клиенте.** Таймзона сервера (UTC на Vercel) может не совпадать с таймзоной пользователя.

## Форма бронирования: решения по UX

- **Модальное окно на нативном `<dialog>`.** `showModal()` даёт top layer, делает фон inert и закрывается по Esc. Начальный фокус — на первом поле, при закрытии фокус возвращается на кнопку, которая открыла окно. Заголовок и подсказка связаны через `aria-labelledby` и `aria-describedby`. На мобиле окно — лист снизу на всю ширину, кнопки во всю ширину.
- **Время — `<select>` с шагом 15 минут.** Опечатки исключены, работает с клавиатуры и на тач-устройствах, на мобиле открывается нативный барабан. 15 минут — компромисс: 30 слишком грубо (встречу 10:15–10:45 не забронировать), 5 даёт 100+ пунктов в списке. Начало: 09:00–17:30, окончание: 09:30–18:00. Шаг — решение интерфейса, а не бизнес-правило: сервер его не проверяет. Если бронь создана с другим шагом, при редактировании её время всё равно показывается.
- **Прошедшее время.** На сегодня прошедшие варианты видны, но недоступны: шкала не «прыгает». На прошедшую дату кнопка «Новая бронь» заблокирована, рядом объяснение, связанное через `aria-describedby`. Начавшиеся брони только для чтения: действий у них нет.
- **Разумные значения по умолчанию.** Форма предлагает ближайший свободный час (или 30 минут, если часа нет нигде). При смене начала окончание сдвигается с сохранением длительности, как в календарях.
- **Живые подсказки по тем же правилам, что у сервера.** `validateBooking` пересчитывается при каждом изменении по актуальному кэшу броней. Ошибки показываются у полей (`aria-invalid` и `aria-describedby`), пересечение — общим предупреждением. В форме виден список занятого времени на выбранную дату, конфликтующие слоты отмечены. Если правила нарушены, отправка не уходит на сервер, а фокус переходит к первому проблемному полю.
- **409.** Форма не закрывается и не сбрасывается. Показывается сообщение со списком броней, с которыми возник конфликт. Список броней перезапрашивается (инвалидация в `onSettled`), чужая бронь появляется в расписании с меткой «Пересекается» (не только цветом). Когда пользователь выбирает другое время, устаревшее сообщение исчезает.
- **Другие ошибки сервера.** 422 с нарушениями — сообщения у соответствующих полей. 404 («бронь удалили») и `BOOKING_LOCKED` («уже началась») — понятное сообщение, повторная отправка не предлагается. Сеть и 5xx — сообщение, что данные на месте и можно отправить ещё раз.
- **Отправка.** Кнопка в состоянии `loading`, поля заблокированы, закрыть окно нельзя, пока запрос не завершится, иначе результат потеряется вместе с окном. Двойной клик и Enter отсекаются отдельной защитой: они успевают раньше перерисовки.
- **Удаление.** Подтверждение в маленьком окне, фокус по умолчанию на «Отмена» как на безопасном действии. После успеха — тост. 404 считаем достигнутой целью: окно закрывается, список обновляется. `BOOKING_LOCKED` объясняется, остаётся только «Закрыть». При сетевой ошибке можно повторить.
- **Без оптимистичных обновлений.** Конфликт — штатный исход, а откат «уже показанной» брони выглядит хуже честного индикатора загрузки.

## Решения по неоднозначностям ТЗ

| Вопрос                                       | Решение                                                                                         |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Чья таймзона определяет «сегодня»            | Таймзона пользователя. Для реального продукта правильнее таймзона офиса с переговорной.         |
| Можно ли менять или удалять начавшуюся бронь | Нет: начавшиеся и прошедшие брони только для чтения (сервер отвечает `422 BOOKING_LOCKED`).     |
| Бронь, начинающаяся в текущую минуту         | Разрешена: прошедшим считается время строго раньше текущей минуты.                              |
| Границы длительности                         | Включительно: ровно 30 минут и ровно 2 часа допустимы.                                          |
| Пустое название                              | Не хранится, в интерфейсе показывается «Без названия».                                          |
| Можно ли перенести бронь на другую дату      | Да: дата — поле формы. После сохранения экран переключается на новую дату брони.                |
| Формат ошибок API                            | `{ error: { code, message, details? } }`. Контракт описан в `entities/booking/api/contract.ts`. |

## CI/CD

`.github/workflows/ci.yml`, запускается на push в `main` и на каждый PR:

1. **quality** — типы, ESLint, Stylelint, Prettier
2. **unit** — Vitest с покрытием (артефакт `coverage`)
3. **build** — `next build`, артефакт сборки передаётся в e2e
4. **e2e** — Playwright на прод-сборке, desktop + mobile; при падении отчёт уходит в артефакты
5. **deploy-preview** — для PR: деплой на Vercel и комментарий со ссылкой
6. **deploy-production** — для `main`: прод-деплой

Деплой идёт только после зелёных проверок. Автодеплой Vercel из Git отключён в `vercel.json`, чтобы на прод не попала непроверенная сборка.

### Подключение деплоя

1. Создать проект на Vercel и выполнить `npx vercel link` локально: появится `.vercel/project.json` с `orgId` и `projectId`.
2. Создать токен: Vercel → Account Settings → Tokens.
3. Добавить секреты в GitHub (Settings → Secrets and variables → Actions): `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`.

Без секретов CI работает полностью, а шаги деплоя просто пропускаются.

### Что не сделано и что бы я делал дальше

По убыванию приоритета:

1. **Создание брони кликом по свободному месту** — таймлайн дня вместо списка. Список выбран как самый доступный и надёжный формат в таймбокс; таймлайн нагляднее показывает «окна».
2. **Таймзона офиса вместо таймзоны пользователя** (см. «Решения по неоднозначностям»). Для одной переговорной это правильнее, но требует данных с сервера.
3. **Фокус после удаления.** Сейчас кнопка-источник исчезает и фокус уходит на `body`; лучше переводить его на соседнюю карточку или заголовок списка.
4. **«Отменить» в тосте удаления** вместо окна подтверждения: быстрее для частого действия.
5. **Автоматическая проверка доступности** (axe в Playwright) и визуальная регрессия.
6. **Настоящий бэкенд.** Сетевой слой к этому готов: достаточно `NEXT_PUBLIC_API_BASE_URL`.
